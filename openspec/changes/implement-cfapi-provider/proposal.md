# Proposal: `implement-cfapi-provider`

## Why

Клиент V1 (rclone mount через WinFSP) отдаёт файлы только через пользовательский процесс смонтированной файловой системы. Windows Cloud Files API даёт то, что требуется V3: нативные плейсхолдеры, pin/hydrate файлов и каталогов, чтение локально гидратированных данных без участия провайдера.

Прототип проверяет это на реальном data path. Ядро juicefs (meta через hub, chunk store, `pkg/fs`) и STS-клиент используются как есть; вместо слоя FUSE/WinFSP пишется адаптер к Cloud Files API.

Это прототип: он проверяет пригодность технологии, а не готовится к выпуску.

## What Changes

- В форке juicefs (ветка от `agio-drive-v2`) добавляется провайдер синхронизации Windows Cloud Files API на Go:
  - `pkg/cfapi` — биндинг `cldapi.dll` через `syscall`, без cgo;
  - `pkg/cfprovider` — движок провайдера.
- Новая команда `juicefs clouddrive`: `register`, `unregister`, `status`, `serve`, `pin`, `unpin`, `ls`, `hash`.
- Чтение: плейсхолдеры из метаданных hub, гидратация по требованию, pin/unpin файлов и каталогов.
- Запись (минимальный цикл): выгрузка новых и изменённых файлов, удаление, переименование, создание каталогов — через NOTIFY-callback'и и write-API `pkg/fs`.
- Регистрация sync root: Win32 `CfRegisterSyncRoot` и ключ реестра Explorer, без MSIX.
- Сборка прототипа — с CGO через mingw gcc. `pkg/compress`, `pkg/meta`, `pkg/chunk`, `pkg/object` не меняются.

## Related Requirements

- **BRD отсутствует** (замечание реестра `specs/index.md`): бизнес-контекст живёт в архитектурном плане v13; настоящий change — инициированное владельцем исследование технологии V3 (сравнение Go / C# / C++ проведено до propose, вердикт — в ADR-005).
- **SRS-001** (Подсистема шифрования, Per-File FEK + Per-Chunk CEK): инвариант change — криптоцепочка FEK/CEK/AGDF не затрагивается; все FR-*/NFR-* SRS-001 по шифрованию сохраняются провайдером как есть (чтение через `pkg/fs` и write-API расшифровывают/зашифровывают существующими механизмами).
- **ADR-004** (Data-plane креденшелы v2: статические per-company ключи): контекст выдачи кредов data plane; прототип упражняет STS-путь (`GetNodeSTSCredentials` через meta proxy, `cmd/render_mount.go`, `cmd/sts_refresher.go`) по решению владельца — ADR-004 не отменяет и не изменяет.
- **ADR-001** (Гибридный spec-driven workflow): правило крупных change — единый change со стадийной декомпозицией в tasks.md применён к лестнице 0–7.
- **ADR-005** (настоящий change, draft): решение о технологии — Go-провайдер с биндингом `cldapi.dll` через `syscall`; альтернативы C# (P/Invoke) и C++ (native) отклонены с обоснованием в ADR-005.

## Capabilities

### New Capabilities

- `domain-cfapi-provider`: провайдер синхронизации Windows Cloud Files API — регистрация, плейсхолдеры, гидратация, pin/unpin, минимальный write-путь.

### Modified Capabilities

Нет. Существующие спеки не затрагиваются:

| Спека | Причина |
|---|---|
| `domain-meta-proxy` | провайдер — обычный клиент `meta.NewClient` |
| `domain-outbox` | поведение не меняется |
| `drive-sts-client` | используется как есть |
| `mount-ownership` | адаптер WinFSP не меняется; владение sync root описано в новом домене |

## Дефолты, подлежащие вето

| № | Дефолт | Отклонённая альтернатива |
|---|---|---|
| D-1 | Регистрация через Win32 и реестр; HKCU, HKLM — только если проба U1 покажет необходимость | MSIX |
| D-2 | Корень `%USERPROFILE%\AgioDrive` на томе NTFS; буква диска не предоставляется | subst или junction |
| D-3 | Автозапуска нет | ключ HKCU Run |
| D-4 | Целевая ОС — Windows 11; используются только функции и callback-типы, доступные с 1709 | опора на новые callback'и Windows 11 |
| D-5 | Bucket и параметры хранения — из format, отданного hub | отдельная настройка |
| D-6 | Write-путь включён по умолчанию; `--read-only` отключает | read-only по умолчанию |
| D-7 | Удаления передаются в backend только для известных плейсхолдеров; удаление sync root не передаётся никогда | передача любого удаления |
| D-8 | Каталог состояния `%LOCALAPPDATA%\AgioDrive\<имя тома>`, флаг `--state-dir` | внутри каталога кэша chunk store |
| D-9 | Линия `implement-windows-mount` не затрагивается | ответвление от неё |
| D-10 | Интеграция с agio-drive (tray, agio-login, supervisor) — отдельный change | включение в этот change |

## Non-Goals

- Shell-расширения: thumbnails, иконки состояний, собственное меню.
- MSIX, подпись, инсталлятор, автозапуск.
- Интеграция с agio-drive: tray, OIDC-логин через agio-login, supervisor. Отдельный change.
- Несколько sync root, аккаунтов, пользователей.
- Обнаружение конфликтов и координация нескольких писателей в одном томе.
- Реактивное обновление дерева при удалённых изменениях: только при старте и при обращении к каталогу.
- Офлайн-доступ к дегидратированным файлам, которых нет в локальном кэше.
- Буква диска и замена V1.
- Чистая сборка без CGO (замена `pkg/compress`) — отдельный change.
- Правки линии `implement-windows-mount`.

## Impact

- Новый код — 3000–4500 строк, все в новых пакетах и `cmd/clouddrive.go`. Исключение — добавляющий метод в `pkg/fs`, если write-API окажется неполным (задача 5.1).
- Сборка: Windows-бинарь требует CGO (mingw gcc) уже из-за `pkg/compress`; прототип не добавляет новых cgo-зависимостей.
- Репозиторий V1 не меняется: `C:\Users\iobukhov\ai\agio\agio-drive`.
- Follow-up change `implement-cfapi-drive-integration`: tray, OIDC через agio-login v0.0.12, supervisor по маркеру готовности. Сейчас блокируется недоступностью GitLab с машины разработки.
- Человеческий слой: новый ADR-005 в `specs/decisions/` + строка в `specs/index.md`.

## Риски

| Риск | Последствие | Что делает прототип |
|---|---|---|
| cldflt.sys работает только на NTFS | корень на другой ФС или сетевом ресурсе не работает | предпроверка ФС в `register` и `serve` |
| Write-путь передаёт локальные правки и удаления в том hub | случайное массовое удаление в sync root уходит в backend | удаление корня не передаётся; передаются только известные плейсхолдеры; `--read-only`; для испытаний выделяется отдельный stage-том |
| Обрыв во время выгрузки | неотправленные данные остаются только локально; staging-файлы juicefs остаются на диске | версия подтверждается одним `Flush`; журнал операций и сверка при старте; очистка staging по U11 |
| Несколько писателей в один том (V1 через rclone, второй клиент) | последний писатель выигрывает, конфликты не выявляются | вне скоупа; ограничение зафиксировано |
| Офлайн | дегидратированные файлы недоступны без meta | pinned и гидратированные файлы читаются без провайдера; остальное — ошибка, а не зависание |
| Усиление чтения: запрос произвольного размера против блока 4 MiB | лишний трафик | кэш chunk store; замер на шаге 3 |
| `cldapi.h` отсутствует в SDK 10.0.26100.0 | layout биндинга не с чем сверить | эталонный header из другого источника, источник и SHA-256 — в design.md |
| CGO-сборка ветки под mingw 10.3 не проверена | вариант α не собирается | задача 0.2 — стоп-точка до написания кода; рецепт уже есть — Makefile-таргет `juicefs.exe` |
| agio-login v0.0.12 недоступен с машины | follow-up блокируется | follow-up вынесен в отдельный change |
| Неопределённости CfAPI U1–U13 | развилки в дизайне | таблица в design.md с запасным вариантом для каждой; закрываются пробами |
