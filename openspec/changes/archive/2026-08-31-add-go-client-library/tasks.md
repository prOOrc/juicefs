## 1. CreateRedisClient (новый файл `pkg/meta/redis_client.go`)

- [x] 1.1 Создать `pkg/meta/redis_client.go` (Apache 2.0 header) с `type redisClientOptions struct{ Options *redis.Options; MinRetryBackoff, MaxRetryBackoff, ReadTimeout, WriteTimeout time.Duration }` и приватной `parseRedisClientOptions(redisURL string) (*redisClientOptions, error)`: scheme-default (`redis://`), `url.Parse`, `queryMap` для `min-retry-backoff`/`max-retry-backoff` (20ms/10s) и `read-timeout`/`write-timeout` (30s/5s) + TLS-параметры (`insecure-skip-verify`, `tls-cert-file`, `tls-key-file`, `tls-ca-cert-file`, `tls-server-name`) + **client-side caching параметры** (`client-cache`, `client-cache-size` 12800, `client-cache-expire` 1m, `client-cache-preload` 0) — разбираются и потребляются (pop) идентично `newRedisMeta` для паритета и синхрона дубликата при ребейзе (сам `redisCache` к сырому клиенту не применяется), `redis.ParseURL`, применение TLS (cert/key, CA pool, ServerName, InsecureSkipVerify), пароль `REDIS_PASSWORD` → `META_PASSWORD` → `META_PASSWORD_FILE` (`readPasswordFromFile`), `MaxRetries = -1`, `MaintNotificationsConfig = &maintnotifications.Config{Mode: maintnotifications.ModeDisabled}`. Вверху файла — комментарий «deliberate duplicate of newRedisMeta option parsing to avoid upstream rebase conflicts; keep in sync on rebase». Файлы: `pkg/meta/redis_client.go`. Проверка: `go build ./pkg/meta/`.
- [x] 1.2 Добавить в `pkg/meta/redis_client.go` экспортируемую `CreateRedisClient(redisURL string) (redis.UniversalClient, error)` с детектом режима по `u.Host`: sentinel (запятая раньше двоеточия) → `redis.FailoverOptions` (`MasterName` = первый сегмент, `SentinelAddrs` = остальные, дефолтный порт `26379`, `SENTINEL_PASSWORD`, копирование pool/retry/timeout полей из `opt`) → `redis.NewFailoverClient`; cluster (несколько хостов через запятую) → `redis.ClusterOptions` (`Addrs`, `MaxRedirects = 1`) → `redis.NewClusterClient`; single → `redis.NewClient(opt)`. Ошибка парсинга → `(nil, error)`. Файлы: `pkg/meta/redis_client.go`. Проверка: `go build ./pkg/meta/`.

## 2. NewMetaClient (новый файл `pkg/meta/client.go`)

- [x] 2.1 Создать `pkg/meta/client.go` (Apache 2.0 header) с экспортируемой `NewMetaClient(uri string, conf *Config) (Meta, error)`: scheme-default (`redis://`), `driver = uri[:index("://")]`, неизвестный драйвер → `return nil, fmt.Errorf("invalid meta driver: %s", driver)` (**без** `logger.Fatalf`), для `mysql`/`postgres` — `setPasswordFromEnv(uri)` (ошибка → вернуть), `conf == nil` → `DefaultConf()` иначе `conf.SelfCheck()`, делегирование `return metaDrivers[driver](driver, uri[p+3:], conf)`. Файлы: `pkg/meta/client.go`. Проверка: `go build ./pkg/meta/`.

## 3. Tests

- [x] 3.1 Создать `pkg/meta/redis_client_test.go` — table-driven тесты `TestCreateRedisClient`: single-node URL (`redis://host:6379`) → `*redis.Client` с `Options().Addr == "host:6379"`; sentinel URL (`master,s1:26379,s2:26379`) → `*redis.Client` с `Options().Addr == "FailoverClient"` (go-redis v9 возвращает `*Client` и для single, и для sentinel — режим различается по маркеру Addr); cluster URL (`redis://h1:7000,h2:7000`) → `*redis.ClusterClient`; URL с client-cache параметрами (`redis://host:6379?client-cache=true&client-cache-size=100&client-cache-expire=30s&client-cache-preload=10`) → корректный single-node клиент (параметры потребляются, не ломают парсинг); невалидный TLS-файл (`rediss://host:6379?tls-cert-file=/nonexistent`) → ненулевая `error`. Файлы: `pkg/meta/redis_client_test.go`. Проверка: `go test ./pkg/meta/ -run 'TestCreateRedisClient'`.
- [x] 3.2 Создать `pkg/meta/client_test.go` — тесты `TestNewMetaClient`: неизвестный драйвер (`unknown://host:1`) → ненулевая `error`, содержащая `unknown`, процесс НЕ завершается (library-safety); валидный драйвер `memkv://test` с `conf == nil` → ненулевой `Meta`, `nil` error (memkv — in-memory бэкенд без внешнего I/O; проверяет nil-conf → `DefaultConf()` путь без паники). Примечание: недоступный single-node Redis НЕ возвращает ошибку из `newRedisMeta` (сбой `ClusterInfo`-пробы глотается, `rdb = c`), поэтому для проверки nil-conf используется memkv. Файлы: `pkg/meta/client_test.go`. Проверка: `go test ./pkg/meta/ -run 'TestNewMetaClient'`.
