# Спецификации: человеческий слой

Эта папка содержит документацию для людей: бизнес-требования, системные требования и архитектурные решения.

## Роль в гибридном workflow

```text
specs/ (эта папка)     →  для людей: зачем и что делаем
openspec/              →  для агентов: как система работает и что меняется
```

Эта папка НЕ заменяет OpenSpec. Она дополняет его бизнес-контекстом.

## Процесс

```text
Идея → BRD → SRS → ADR (если нужно) → OpenSpec Propose → Apply → Archive
```

### BRD

Бизнес-требования. Отвечает на вопросы: зачем делаем, какую проблему решаем, кто пользователь, какой результат ожидаем, как измерим успех, что входит/не входит в скоуп.

### SRS

Системные требования. Отвечает на вопросы: что должна делать система, какие роли и акторы, функциональные/нефункциональные требования, ограничения, ошибки и крайние случаи, требования к безопасности и данным. Требования имеют стабильные ID: `REQ-*`, `NFR-*`, `SEC-*`, `DATA-*`.

### ADR

Архитектурные решения. Создаётся, когда принимается важное решение: выбор технологии, архитектура, схема данных, безопасность, интеграции.

## Структура

- `brd/` — бизнес-требования (зачем делаем).
- `srs/` — системные требования (что система должна делать).
- `decisions/` — архитектурные решения (ADR).
- `templates/` — шаблоны документов.
- `index.md` — реестр всех документов.

## Как это связано с OpenSpec

Когда создаётся change в OpenSpec, в proposal.md указываются ссылки на документы из этой папки:

```markdown
## Related Requirements
- BRD-001: Seat-based Billing System
- SRS-001#REQ-003: ...
```

Это даёт трассируемость:

```text
Бизнес-цель (BRD)
  → Требование (SRS)
    → Поведение системы (openspec/specs/ — Source of Truth)
      → Изменение (openspec/changes/ — Delta Spec)
        → Код
```

## Именование файлов

- `brd/BRD-NNN-short-slug.md`
- `srs/SRS-NNN-short-slug.md`
- `decisions/ADR-NNN-short-slug.md`

ID стабильны: не меняются после присвоения. Если документ устарел — помечается `DEPRECATED` с причиной и заменой, а не удаляется.

## Статусы

- `draft` — черновик.
- `needs-input` — нужны уточнения.
- `review` — готов к ревью.
- `approved` — утверждён.
- `implemented` — реализован (для BRD/SRS, чьи требования уже в коде).
- `archived` — архивирован.

## Правила

1. BRD и SRS пишутся для людей, не для агентов. Они могут быть менее формальными, чем OpenSpec specs.
2. Они задают контекст и требования верхнего уровня, а не точное поведение. Точное поведение описывается в `openspec/specs/`.
3. Не дублируй OpenSpec specs сюда. Здесь — бизнес-уровень.
4. Каждый новый документ добавляй в `index.md`.
5. Используй шаблоны из `templates/`.
6. Не храните секреты, токены, пароли и персональные данные в этой папке.
7. Если требование неоднозначно — добавь открытые вопросы и статус `needs-input`.
